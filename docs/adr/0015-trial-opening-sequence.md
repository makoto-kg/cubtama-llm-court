# 0015: 裁判型の開廷の場面・証言の読み上げと法廷の画面

- 日付: 2026-09-28
- 状態: 採用

## 背景

裁判型の画面は、事件の概要と証言台がいきなり並ぶ作りで、法廷バトルADVらしい「開廷」の流れがなかった。ユーザーから次の流れの要望があった。

- 裁判長が挨拶し、事件のごく短い概要を紹介する
- 原告側・被告側が宣言する
- 審理が始まる

画面の作りと流れはジャンルの定番(法廷バトルADV)に寄せたい。ただし、既存作品の素材・意匠・固有名詞は使わない(AGENTS.md)。オフラインモード(ADR 0014)でも同じ体験にする。

## 決定

- 開廷の場面をフロントエンドの表示として追加する(`components/OpeningSequence.tsx`)
  - 台本は事件の公開データ(題名・概要・最初の証言の証人)から規則で組み立てる(`lib/opening.ts`)。LLM は使わない
  - 流れ: 「開廷」のカットイン → 裁判長の挨拶(木槌)→ 超概要(概要の最初の 1 文)→ 原告側の宣言 → 被告側の宣言 → 最初の証人を呼ぶ(木槌)→ 「審理開始」のカットイン → 尋問の画面
  - 原告側 = プレイヤー(証言の矛盾を追及する側)、被告側 = 証人の証言を支える側とする。事件のデータには当事者がいないため、宣言は定型文にした
  - 最初に呼ぶ証人は、いま尋問する証言の証人(矛盾のない証言を飛ばした後)
- 見せるのは尋問が始まる前だけ(`shouldShowOpening`)。スキップできる。クリック・Enter・Space で台詞を送る
- ゲームの状態・イベントは変えない(演出だけ)。バックエンドの変更はない
- 証言が始まったら、まず証人に証言の行を一通り話させ(タイプライター表示)、読み終えてから尋問の操作(つきつける・ゆさぶる)を出す(`components/TestimonyRecital.tsx`)
  - 流れ: 「証言開始」のカットイン → 証言の題名を掲げ、行を 1 行ずつ表示(読み終えたら自動で次の行へ。クリック・Enter で早送り)→ 「尋問開始」のカットイン → 尋問
  - 証言の行は事件のデータのまま出す(LLM で言い換えない。ADR 0013)。証言の行は台詞と色を分ける
  - 矛盾を崩して次の証言に移るときは、証人の応答とカットインが終わってから、前の応答を残したまま「次の証言を聞く」で読み上げを始める(応答を読む前に画面が切り替わらないように)
  - 尋問を始めた証言(その証言の行への行動がある)を再開したときは読み上げない(`testimonyExamined`)。「証言をもう一度聞く」で聞き直せる。スキップもできる
- 台詞送り(タイプライター・自動送り・キー操作)は開廷の場面と共通のフック(`hooks/useDialogue.ts`)にした
- 法廷の画面の部品(`components/CourtScene.tsx`)を追加し、尋問の画面の証言台もこれに揃えた
  - 話す人ごとに画面(裁判長席・原告席・被告席・証言台)を切り替える
  - 画面の下に名札付きの台詞の枠を重ね、読み終わったら「次へ」の印を出す
  - 背景・机・カットインの文言はオリジナル。原告側・被告側の立ち絵は、当面ディベートの仮素材を流用する(`assets/manifest.ts`)

### スマホの縦画面(2026-09-29 追加)
- スマホの縦画面で、スクロールせずに遊べるようにした。キャラクターと台詞は画面に固定する
- プレイ中の画面を `GameShell` にした。lg 未満では画面いっぱいに固定し、上から次の順に並べる
  - 状態のバー: 事件名・操作 / ゲージ・矛盾の数・証拠品・記録
  - 法廷の画面: 高さは画面の約半分
  - 操作の欄: スクロールするのはここだけ
- 広い画面では、従来どおり右の列に概要と尋問の記録を出す
- 尋問の操作を、行の一覧から次の形に変えた(`ExaminationPanel`)
  - いま指している証言の行を ◀ ▶(または行の番号)で切り替える
  - 選んだ行に「ゆさぶる」か「つきつける」を選ぶ。つきつけるは証拠品ファイルを開き、その行に並んだ証拠品から選ぶ
  - 指している行は、台詞の枠に証言の色で出す。台詞の枠をタップすると次の行へ進む
  - 証人の応答は、行を指し直すまで台詞の枠に残る
- 証拠品ファイルは、今の画面(法廷)の上に重ねて出す(`EvidenceOverlay`)。状態のバーの「証拠品」から開く
  - 「つきつける」から開いたときは、その行に並んだ証拠品に「つきつける」ボタンを出す。証拠品の詳細を見ながら選べる
- 人物・事件の概要・尋問の記録は「記録」のドロワーにまとめた(`CourtRecord`)
- 全矛盾を解いたら、崩れた応答を読んでから「最後の問いへ」で問いに移る。問いは裁判長の画面で出す

## 理由

- 台本を規則で作れば、オンライン・オフラインで同じ場面になり、事前生成のパックも作り直さずに済む
- 演出だけなのでイベントにしない。状態の真実(イベントログ・オフラインの行動の列)に影響しない
- 途中から再開した裁判で毎回開廷の場面が出るのは煩わしいため、尋問前に限った
- 証言を聞く前に選択肢が並ぶと、行を読まずにつきつけてしまう。ジャンルの定番どおり「証言を聞く → 尋問する」の順にした
- 全行の選択肢を並べると、スマホでは縦に長くなる。1 行ずつ指して操作する形なら、操作の欄は行の数によらず一定の高さに収まる

## 影響

- 宣言が定型文なので、事件ごとの個性はない。事件生成で当事者と冒頭の主張を作るなら、そのときに差し替える
- 尋問の前にページを読み直すと、開廷の場面・証言の読み上げがもう一度出る(スキップで飛ばせる)
