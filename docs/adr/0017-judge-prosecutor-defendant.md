# 0017: 法廷の登場人物を裁判官・検察官・被告の 3 人にする

- 日付: 2026-09-29
- 状態: 採用(ADR 0013・0015 の一部を置き換える)

## 背景

裁判型では、プレイヤー(弁護側 / 原告側)が複数の証人を尋問していた。開廷の場面(ADR 0015)には、原告側・被告側(代理人)の宣言もあった。

ユーザーから次の要望があった。
- 法廷の登場人物を、裁判官・検察官・被告の 3 人にする
- 検察官が被告を直接尋問する形にする

事件データには当事者の欄がなかった。生成済みの事件では、複数の人物が証言している。そのため、画面の表記を変えるだけでは実現できない。

## 決定

### 事件(domain・生成)
- `Case` / `CasePublic` に `defendant_id`(被告)を追加する
- 被告だけが証言し、嘘をつく。整合性チェック(`check_case`)で次を確かめる
  - 被告が決まっている(`missing_defendant`)
  - 嘘・証言・台本がすべて被告のもの(`lie_not_defendant` / `testimony_not_defendant` / `script_not_defendant`)
- 事件生成の下書き
  - 真相の下書きで `defendant_key` を選ばせる。嘘の話し手は書かせず、すべて被告にする
  - 資料の下書きでは、証言の話し手を書かせない(すべて被告)。台本は被告の 1 本(`script`)にする
  - 被告の役割は「被告(〜)」の形にさせる
  - 被告以外の人物は法廷で証言せず、真相と証拠品にだけ登場する
- 最後の問いは「誰が偽ったか」ではなく、実際に起きたことや被告が偽った理由を問う(偽ったのが被告なのは前提)

### プロンプトと表記
- 被告役は、証言した被告として検察官の尋問に答える(`witness/respond.j2`)
- 逸脱の検査(`judge/witness_deviation.j2`)・solver も、被告と検察官の表記にした
- CLI・進行中の表示・評価レポートの「証人」は「被告」にした
- 役割名(`models.yaml` の `witness`)、API のフィールド名(`witness_id` など)、イベント名は変えない
  - 手元の設定(`models.local.yaml`)と保存済みのログをそのまま使えるようにするため
  - `witness` は「証言台に立つ人(= 被告)」を指す内部名として扱う

### フロントエンド
- 法廷の画面(`CourtShot`)は、裁判官席・検察官席・証言台(被告)の 3 つにした
- 開廷の場面の流れ
  - 裁判官: 挨拶 → 超概要 → 被告の紹介 → 「検察側、準備は」
  - 検察官(あなた): 宣言
  - 裁判官: 被告を証言台に呼ぶ
  - 被告: 宣言
  - 裁判官: 「検察官による被告人尋問を始めます」
- 表示名は `TRIAL_ROLE_NAMES`(裁判官・検察官・被告)にまとめた。ディベート型の表記(裁判長・肯定側・否定側)は変えない
- 名札(2026-10-01 追加)
  - 裁判官は「アヤ（裁判官）」にする。どの事件でも同じ人物なので、名前は画面の素材の設定(`assets/manifest.ts` の `JUDGE_NAME`)に置く
  - 被告は「名前（被告）」にする
  - 検察官は、事件に演じる人物(`Case.prosecutor_id`。公開)があれば「名前（検察官）」、なければ「検察官（あなた）」にする
  - 台詞の中の名前は変えない(`lib/roles.ts`)
  - チュートリアルでは、同居猫のタマが検察官を演じる
- 検察官の口調(2026-10-01 追加)
  - 検察官の定型文(開廷の宣言、ゆさぶる・つきつけるの台詞)は、事件の `prosecutor_speech`(公開)で口調を選ぶ
    - `plain`: ふつうの口調(既定)
    - `cat`: 猫言葉(「〜にゃ」)
  - チュートリアルは猫言葉
  - 猫言葉の検察官は、つきつけるときの台詞を「異議ありにゃ！」から始める
  - つきつけるときのカットインも、猫言葉なら「反証!」の代わりに「異議ありにゃ！」を出す(ユーザーの指定)
    - カットインの文言は「既存作品の決め台詞を使わない」方針(`lib/cutin.ts`)の例外として扱う
    - ふつうの口調の事件では「反証!」のまま
- 被告は `defendant_id` で決める。被告のない旧形式の事件では、役割が「被告」で始まる人物を被告とする。それもなければ、最初に証言する人を証言台に呼ぶ

### 同梱データ
- 旧形式の生成済みパック 2 件(週休3日制・ベーシックインカム)は同梱から外した。新しい形式で作り直したら戻す
- チュートリアル(ADR 0016)は、もともと被告だけが証言する形。`defendant_id` を足して作り直した

## 理由

- 被告を事件データに持たせれば、生成・チェック・画面が同じ根拠で被告を扱える。役割の文字列から推測しなくて済む
- 嘘の話し手を LLM に選ばせないことで、「被告以外が嘘をつく」下書きが構造上作れなくなる
- 内部名を変えないのは、設定・保存済みデータの互換を保つため。表記の変更に比べて得るものが少ない

## 影響

- 旧形式の事件(`defendant_id` なし)は読み込めて遊べる。ただし `case validate` のチェックには通らない。作り直すには `case generate` で再生成する
- 同梱の事件は当面チュートリアルだけになる。生成済みの事件をパックにするには、ローカルの LLM サーバーで次を実行する
  - `case generate`
  - `offline export`
- 被告の宣言は定型文。猫の被告でも口調は変わらない。事件ごとに変えるなら、事件データに冒頭の台詞を持たせる
- 検察官の立ち絵は、ディベートの肯定側の仮素材を流用している
