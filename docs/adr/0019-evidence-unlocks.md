# 0019: 尋問の中で手に入る証拠品

- 日付: 2026-09-30
- 状態: 採用

## 背景

チュートリアル(ADR 0016)を、もう少し長く楽しめるようにしたいという要望があった。特に次の点を求められた。
- 被告の好きなチュールの味を、尋問中の会話から新しい証拠品として手に入れる

これまでの裁判型では、証拠品はすべて初めから手元にあり、尋問の中で増えることはなかった。

## 決定

- 事件に「尋問の中で手に入る証拠品」を持たせる(`Case.evidence_unlocks` / `EvidenceUnlock`)
  - 手に入れる行動は次のどちらか
    - 証言の行を「ゆさぶる」
    - 証言の行に証拠品を「つきつける」
  - 非公開の情報として扱う。手に入れるまで、法廷記録(公開の証拠品)に出さず、つきつける選択肢にも並べない
- 手元にある証拠品は、選択済みの行動から決める(`Case.available_evidence_ids`)
  - 新しいイベントは足さない。状態は、これまでどおりイベントログ(オフラインは行動の列)から作り直せる
- 分析官(backend・オフラインの両方)
  - 手元にない証拠品は並べない
    - 正解の証拠品が手元にない矛盾は、手に入れるまで正解の組が並ばない
  - まだ証拠品を手に入れていない行動は、無作為に選ばず必ず並べる(見逃して詰まらないように)
    - 無作為に選ぶ候補からは外す。手に入る証拠品のない事件では、並び方は変わらない
- 公開の事件(`CasePublic`)の証拠品は、手元にあるものだけにする
  - オンライン: `TrialView.case`
  - オフライン: `toTrialView`
  - オフラインのパックには、すべての証拠品と手に入れる行動(`answers.unlocks`)を入れる。手元にあるかは、ブラウザが行動の列から決める
- 事前シミュレーション・台本のパック(`enumerate_actions`)
  - 手に入る証拠品は、手に入れる行動がある証言と、それより後の証言でだけつきつけられる行動として数える
- 整合性チェック
  - 手に入れる行動の参照が正しい
  - 1 つの証拠品を手に入れる行動は 1 つだけ
  - 矛盾の正解の証拠品を、その証言より後の証言でしか手に入れられない事件にしない(`unreachable_unlock`)
- 画面: 手に入れた応答を読み終えたら「証拠品を手に入れた!」の知らせを法廷の画面に重ねて出す(`NewEvidenceNotice`)
  - 「法廷記録に加える」で閉じるまで、次の操作はできない
- 台本の事件は、嘘(矛盾)の数の上限もモードの既定から緩める(事件生成の範囲に縛らない)
- チュートリアル「消えたチュール事件」を、証言 2 本・矛盾 4 つ・証拠品 6 つに広げた
  - 足跡(肉球の大きさ)
  - 空の袋(毛の色)
  - 戸棚の扉(開けるのに要る重さと体重)
  - カブの証言(証言 2 の 3 行目をゆさぶると手に入る。好きな味)

## 理由

- 手元にある証拠品を行動から決めれば、進行の規則は増えても、状態の真実(ログ)の形を変えずに済む
- 手に入れる行動を必ず並べないと、選択肢の無作為な組み合わせ次第で先に進めなくなる
- 公開の事件から手元にない証拠品を外せば、表示・solver・CLI が同じ根拠で扱える

## 影響

- 事件生成(Phase 8)は、まだ手に入る証拠品を作らない。台本の事件でだけ使う
- 規則は Python と TypeScript の二重になっている(ADR 0014)。両方に同じ観点のテストを置いた
  - Python: `test_evidence_unlock.py`
  - TypeScript: `engine.test.ts`
