# 0010: CLI でのプレイ(シナリオ検証用の簡易モード)

- 日付: 2026-09-26
- 状態: 採用

## 背景

PLAN にはないが、フロントエンド(Phase 7)なしで人間 vs LLM を試し、分析官の選択肢や代弁者の清書、ペナルティの動きといったシナリオを手早く検証したいという要望があった。本格的なゲーム画面ではなく、確認用の道具として位置づける。

## 決定

- `llm-court play "<テーマ>" [--side negative] [--rounds 1] [--evidence 捜査結果.json] [--reveal] [--resume ID]` を追加する
- API を経由せず `DebateEngine` を直接動かす。進行は API と同じエンジン操作(`start` → `collect_evidence` → `run_to_end` → `choose`)で、イベントも同じストア(`data/llm_court.db`)に残る
- 発言は `debate` と同じ `ConsoleObserver` でストリーミング表示する。人間の手番では、選択肢を表にして番号で選ばせる(Rich の `Prompt`)
- 検証向けの機能
  - `--reveal`: 選ぶ前に強さと判断理由を表示する(通常は選択後にだけ表示)
  - 選択肢と判断理由は省略せず、折り返して全文を表示する
  - `q` で中断でき、`--resume <セッション ID>` で再開できる。状態はイベントログから再構築する
  - 終了時に JSONL・Markdown の法廷記録と計測サマリを保存・表示する(`debate` と共通)
- 対話の本体は `cli/play.py` の `PlayLoop` に分け、入力関数を差し替えられるようにする(テストでは CliRunner の入力を使う)
- `debate` と `play` で共通のエンジンの組み立てと出力保存は、`cli/main.py` の `_engine_context` / `_save_outputs` にまとめた

## 理由

- エンジンが段階実行(ADR 0008)と人間の手番(ADR 0009)に対応済みなので、CLI は表示と入力だけを担えば済む
- API と同じエンジン操作を使うため、CLI で検証したシナリオの挙動は API・フロントエンドでも同じになる

## 影響

- 実行中に、代弁者が人間側の立場から外れる清書(肯定側なのに慎重論で締める)を確認した。代弁者のプロンプトに、立場を固定するルールを追加した
- PLAN にない機能だったため、PLAN の Phase 6 に「CLI での簡易プレイ」の項目を追記した
