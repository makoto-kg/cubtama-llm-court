# 0016: 台本のオフラインパック(チュートリアル)

- 日付: 2026-09-28
- 状態: 採用

## 背景

オフラインモード(ADR 0014)で遊び方を覚えるための、ごく簡単なチュートリアルの事件が欲しいという要望があった(猫がチュールを盗んだ事件)。

既存のパックは、事件生成(Phase 8)で作った事件の全行動に対する証人の応答を、LLM で事前に生成して作る。チュートリアルには合わない。
- 応答を一字一句決めておきたい(遊び方を教える台詞にしたい)
- 事件も、事件生成の規模の下限(嘘 2 個以上など)より小さくしたい
- 出典は現実の資料ではなく、事件の中の証拠品でよい

一方で、パックを手で編集しない(`frontend/AGENTS.md`)という決まりは保ちたい。

## 決定

- 人が書いたシナリオファイル(YAML。`backend/scenarios/`)から、LLM を使わずにパックを作る `llm-court offline scripted <file...>` を追加する(`offline/scripted.py`)
  - シナリオには事件の全体(`Case`)と、起こりうる全行動に対する応答(行動キー → 応答)を書く
  - パックを作る前に検証する。どれかに当てはまればエラーにして、パックを書かない
    - 事件の整合性チェック(`check_case`)に通らない。嘘の数の下限だけ 1 に緩める
    - 応答が足りない、または余る
    - 応答が空
  - 同じ入力から同じパックになるよう、生成日時には事件の作成日時を使う。同梱のパックがシナリオと一致することをテストで確かめる
- パックのメタ情報に次を追加する
  - `source`: `simulated`(LLM で事前生成)/ `scripted`(台本)
  - `tutorial`
- 一覧(`index.json`)にも `tutorial` を載せる。並び順はチュートリアルを先頭にし、残りは生成の古い順にする
- 答え・モードの組み立ては、事前シミュレーションと共通の関数(`pack_answers` / `pack_mode`)にした
- 学習ポイントの出典の URL は空にしてよい。フロントエンドは、URL が空ならリンクにせず題名だけ出す(事件の証拠品を出典にする場合)
- 開廷の場面では、役割が「被告」で始まる人物がいれば、裁判長が概要の後で被告を紹介する(ADR 0015 の追加)
- 最初のチュートリアル「消えたチュール事件」(`scenarios/tutorial-churu.yaml`。ADR 0019 で証言 2 本・矛盾 4 つに広げた)
  - 被告の茶トラ白猫カブが証言する。証言は 1 つで 3 行。矛盾は 1 つ(罠 1 つ)、証拠品は 3 つ

## 理由

- 台本をファイルにしてコマンドで変換すれば、パックを手で編集せずに済む。レビューできるのはシナリオファイルになる
- 応答の過不足を機械的に調べられるので、行動の組み合わせが増えても書き漏れがない
- 事件のモデル(`Case`)をそのまま使うので、解説・進行の規則はほかの事件と同じになる

## 影響

- 台本の応答は逸脱の検査をしない(`check` は空)。書いた人が責任を持つ
- 台本の事件でも、応答は「全行 × 全証拠品」の組の数だけ要る。証言の行や証拠品を増やすと、書く量が掛け算で増える
- 被告の紹介は役割の書き方で決めていた。ADR 0017 で事件データに `defendant_id` を持たせ、そちらで決めるようにした
- 既存のパックのファイルには `source` / `tutorial` がない。既定値(`simulated` / `false`)で読まれる
- 立ち絵は人物ごとに変えられない。猫の証人も、共通の証人の仮素材で表示される
