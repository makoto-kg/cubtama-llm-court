# 0005: 捜査パイプライン(証拠品化)

- 日付: 2026-09-23
- 状態: 採用

## 背景

Phase 2 で、テーマから Web の情報を集め、引用の実在が検証された証拠品(`Evidence`)を作る。
LLM は本文にない「引用」を作ることがあるため、機械的な照合で裏付けを確認する必要がある。

## 決定

### 流れ
researcher が検索クエリを生成 → SearXNG で並行検索 → 各クエリの結果を順位ごとに交互に並べて重複除去 → 上位 `max_pages` 件の本文を取得 → researcher がページごとに `EvidenceDraft` を生成 → 引用照合 → 上位 `target_evidence` 件に `EV-01`… の ID を振る。

### 取得の制限
- robots.txt をホストごとに 1 回取得して従う。401/403 は全面禁止、その他の取得失敗(404・5xx・通信エラー)は制限なしとして扱う
- タイムアウト(`fetch_timeout_s`)、サイズ上限(`fetch_max_bytes`、Content-Length とストリーム中の両方で確認)、`Content-Type` が HTML 以外は除外(PDF は現時点で対象外)
- 同時取得数は `fetch_concurrency`。User-Agent は `research.user_agent`
- 本文抽出は trafilatura(`favor_precision`、公開日も取得)。CPU 処理なので `asyncio.to_thread` で実行

### キャッシュ
- 抽出済みの本文を `cache_dir/pages/<URL の SHA-256>.json` に保存し、同じ URL は再取得しない。失敗はキャッシュしない
- 有効期限は設けない(必要になったら追加する)

### 重複除去
- URL はスキーム・`www.`・フラグメント・末尾 `/`・トラッキング引数(`utm_*`、`fbclid` 等)を正規化して比較する
- タイトルは NFKC・末尾のサイト名(「 | サイト名」等)を除いて比較する。いずれかが一致したら後の結果を捨てる

### 引用照合
- 照合前に両方を正規化する: NFKC、空白・改行・ゼロ幅文字の除去、引用符(「」『』“”)とダッシュ類の統一、小文字化
- 正規化後の部分文字列一致を検証済みとする。省略記号(…、...)で区切られた引用は、各断片がこの順に出現すれば一致とみなす
- 正規化後 8 文字未満の引用は偶然の一致を避けるため検証済みにしない
- 照合は LLM に渡した切り詰め後の本文ではなく、取得した本文全体に対して行う

### 未検証の事実の扱い
- 未検証の事実は `quote_verified=false` のまま証拠品に残し、表示でも明示する。後続フェーズでは `Evidence.verified_facts` だけを論拠に使う想定
- 検証済みの事実が 1 件もないページは証拠品にせず、除外理由を記録する

### 失敗の扱い
- 一部のクエリの検索失敗は無視し、すべて失敗したら `SearchError`
- ページ単位の LLM 失敗(構造化出力の失敗、コンテキスト超過などのサーバーエラー)はそのページだけ除外する。LLM サーバーへの接続失敗は全体を中断する

### 設定
- `Settings.research`(`ResearchSettings`)にまとめ、環境変数は `LLM_COURT_RESEARCH__<項目>` で上書きする(`env_nested_delimiter="__"`)
- LLM に渡すページ本文の長さ `max_chars_per_page`(既定 6000 字)はモデルのコンテキスト長に依存するため設定値とし、`research --max-chars` でも指定できる

### ドメインモデル
- `Evidence` に PLAN §4 にない `published_date`(ページの公開日。不明なら None)を追加した。最新情報を扱うディベート型で情報の新しさを判断するため
- 除外した情報源と理由を `SkippedSource` として `ResearchReport` に残す

## 理由

- 引用照合を LLM ではなく文字列照合にすると、判定が決定的でテストでき、LLM の自己申告に依存しない
- 未検証の事実を捨てずに残すと、捏造の傾向を後で分析でき、ゲーム内の「偽証」表現にも使える

## 影響

- 正規化照合は語尾の言い換えや、途中を省いた継ぎ合わせを未検証として扱う(実行例では事実の 88〜94% が検証済み)
- 情報源の信頼性(Q&A サイトや個人ブログ等)はまだ評価していない
